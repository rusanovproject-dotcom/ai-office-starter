# Содержательный аудит Демиурга

2026-11-07. Проверка read-only; исходники, индекс, manifests и чужие guide-правки не менялись. Проверены core/card/memory, office-hire, hire.py, registry.py, все четыре templates, test_hiring.py и baseline735c3e6. Claude/внешние сервисы не запускались. Это сценарная и механическая проверка, не новый model smoke.

Вердикт: минимальная локальная сборка роли реализована; полноценная фабрика специализированных сотрудников не подтверждена. Старый core был заглушкой; новый core вместо неё связывает работающую процедуру найма. Пустая память Демиурга ожидаема для чистого офиса. Общая процедура office-hire доступна в каноне и Claude-копии; native subagents она честно не создаёт.

## Подтверждённые недостатки

1. **P1, потеря специализированной методики в шаблонах.** content-voice.md, sales-lite.md, niche-helper.md и _universal-core.md теперь побайтно одинаковые универсальные заготовки. В baseline content-voice имел процедуру чтения реальных образцов, снятия voice-dna, fallback без выдуманного голоса и сохранения поправок; sales-lite — разбор разговора → карточка → КП → следующий контакт с разграничением подготовки и отправки. Сейчас эти различия исчезли, а office-hire не отсылает к заменяющим специализированным методикам. Минимум: вернуть предметные разделы в три заготовки, сохранив общий канон/registry/новые границы полномочий; исходники компетенции должны различаться по профессии.

2. **P1, template-only источника достаточно для программной активации.** create_employee проверяет только is_file для sources; niche-helper сейчас содержит только плейсхолдеры. В изолированной синтетической копии реально выполнено create_employee с source niche-helper, method «Дай ответ по вопросу», затем activate_employee с task «Ответить на учебный вопрос», output «Ответ подготовлен», confirmed:true. Получен status active без содержательного предметного источника, артефакта результата и критерия оценки. office-hire словесно требует реальную пробу/негативный сценарий/доменное ревью эксперта, но эти evidence в activate schema не представлены. Это не доказательство ложного model поведения; это достижимая формальная активация неполной роли. Минимум: отвергать шаблон-заготовку как единственный источник компетенции, хранить проверяемый путь результата и оценку по критерию; экспертный статус отделить от простой локальной роли и требовать независимый verdict для него.

## Что есть и чего нет

Есть: конкретная цепочка create draft → core/card/memory/registry → owner-confirmed activation; защита коллизий; ссылки на каноны и ограничения доступа; штатная карточка/память Демиурга. Нет: привязанных предметных skills для голоса/продаж/нишевой экспертизы; реального предметного корпуса в заготовках; автоматической установки native subagents или host skills. Нового сотрудника нельзя считать экспертом только потому, что созданы три файла.
