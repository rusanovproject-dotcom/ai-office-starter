# Аудит Риты: нужна доработка

Read-only сценарный аудит 2026-11-07. Проверены AGENTS, registry, core/memory Риты, office-tidy, office-ingest, этап8 и stage_check; сравнение с 735c3e6. Claude и новая модельная CLI-проба не запускались. Изменён только этот отчёт.

## Что есть

Core сокращён с развёрнутого baseline до 11 строк, но основные безопасные обязанности сохранены в core + реальном office-tidy: карты/INDEX/ссылки, канон profile/work/goals, проверенная копия перед консолидацией, запрет внешней отправки и фоновых обещаний. Нужные office-tidy и office-ingest существуют. Office-ingest прямо передаёт текучку Рите после знакомства. Отдельная внешняя экспертная база для этой роли не нужна: методика опирается на структуру самого пакета.

Пустой memory.md и отсутствующая персональная card в чистом шаблоне — нормальны для status draft, а не утрата клиентских данных. Готовой активной Ритой этот шаблон считать нельзя.

## Подтверждённые дефекты

1. **P1: этап8 может закрыться при draft, оставляя Риту неподключённой.** В синтетической временной копии создана полная card с четырьмя полями и валидная MAP; штатная memory существует. При неизменном registry status draft `check_stage(root,8)` вернул `PASS:structure-only`. В stage8 требуется «зарегистрируй», но нет явной активации после пробы/подтверждения; employee() не проверяет active. Core и office-tidy при этом запрещают представлять draft как подключённую Риту. Минимум: явная процедура активации с подтверждением, затем readiness требует active для завершённого этапа. Это тот же класс дефекта, что для Директора, без отдельной дублирующей механики.

2. **P2: потерян обязательный цикл собственной памяти.** Baseline core завершался «перед задачей — прочитала свою память, после — дописала. Фейл — записала». Текущие core и office-tidy не требуют записи решения/результата после уборки, хотя неизменённая memory.md всё ещё ссылается на «императив в core.md». Сценарий: Рита исправляет индекс и завершает отчётом по последнему абзацу; обязательного шага сохранить выбор структуры нет, следующий чат не получает решения. Минимум: вернуть чтение нужного хвоста и append датированного решения/лога уборки, не копируя биографию или цены; конкретизировать 200 строк и архив рядом с исходным файлом с сохранением цитат.

## Проверенные сценарии

| Запрос | Оценка |
|---|---|
| Исправить сломанную ссылку INDEX в разрешённом объёме | Процедура есть; повторное разрешение не требуется |
| Сократить память с запрещённым личным фактом | Копия и архив не обходят запрет; явные границы есть |
| «Что ты обо мне знаешь» | Есть разрешённый краткий пересказ без вываливания клиентских карточек |
| Включить Риту на этапе8 | Подтверждён ложный PASS при draft |
| Запомнить принятое правило раскладки после уборки | Обязательное сохранение собственного решения потеряно |

Вердикт: это не пустой файл и skills не отсутствуют, но функциональная полнота просела в памяти и вводе в работу. Полноценность PASS не заявлена.
