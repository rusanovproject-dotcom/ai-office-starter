# Клиентский AI-офис НейроШтаба

Один локальный офис: общие инструкции, профиль, проекты, сотрудники и память для Codex и Claude Code. Канон — `AGENTS.md`; `CLAUDE.md` импортирует его. Навыки находятся в `.agents/skills/`, Claude-копия создаётся автоматически без symlink.

Проверено на macOS arm64, Python 3.14.6, Codex CLI 0.166.0. Модельные проверки Claude Code и переключение Codex ↔ Claude **SKIPPED по решению владельца**. До этого отдельно проверялся SessionStart установленного Claude Code 2.1.319; это не приёмка поведения модели. Windows, Linux и Codex Desktop отдельно не проверены. Нужен Python 3.10+ со стандартной библиотекой; нижняя граница и другие ОС не проходили runtime-проверку.

## Начать

Распакуйте ZIP в отдельную папку. В терминале из корня:

```bash
python3 office-start.py codex
# либо, когда выбран и настроен Claude Code:
python3 office-start.py claude
```

Клиент должен быть установлен и авторизован в собственном аккаунте. Launcher сначала выполняет локальную проверку, затем открывает клиент из правильного корня. Работает и без Git. При вызове из глубокой подпапки сохраняет текущий проект через переменную только этого процесса, а не общий файл «текущий проект».

В Codex при первом запуске прочитайте определения `/hooks` и доверяйте только проверенной копии. Доверие хранится у клиента; офис его не обходит. Изменение исполняемых процедур меняет fingerprint определения, новая версия требует нового native review. Без доверия автоматические хуки не работают. Для открытия папки напрямую в приложении читайте корневой AGENTS и явно запускайте bootstrap; инструкция модели не равна технической защите. [Контракт Codex hooks](https://learn.chatgpt.com/docs/hooks).

Без Git нет Git-гейта и обновление состояния покажет `SKIPPED:not-git`, а не успешную установку. Если Git есть, bootstrap проверяет именно этот репозиторий и его `pre-push`. Чужой репозиторий, внешний hooksPath и чужой pre-push не перезаписываются. Snapshot хранится локально в `.office/snapshots/`, не создаёт коммит и не добавляет файлы в индекс.

Напишите «Привет» для знакомства или сразу дайте рабочую задачу. Анкета необязательна; известное не спрашивается заново. Можно пропустить личный вопрос и запретить сохранение. Офис не управляет историей чата самого клиента.

## Память и работа

| Что | Канон |
|---|---|
| Человек и постоянные предпочтения | `me/profile.md` |
| Цели по областям и срокам, даже без коуча | `me/goals.md` |
| Текущие факты дела и цены | `work/map.md` |
| Проект и его правила | `projects/<slug>/AGENTS.md`, `map.md` |
| Клиент | `clients/<slug>/README.md` |
| Ход знакомства и продолжение | `team/ops/build-log.md`, `threads.md` |
| Сотрудники | `team/registry.json`; `team/map.md` производный |
| Готовое | `results/` или папка выбранного проекта |

Подтверждённый профиль записывает `scripts/office/personalize.py`; он пересобирает только owner-блок корня и выжимку. Эти представления отдельно не редактируются. Поправка цены обновляет её источник; старая презентация не откатывает текущий факт. Предпочтения меняют действия и объяснения, а не полномочия.

«Создай сотрудника» запускает законченный локальный найм: потребность → методика и примеры → draft → реальная проба → подтверждение → active. Имя и алиасы отделены от роли. В этом пакете сотрудники работают как роли текущего чата; создание файлов не запускает native subagent или фоновый процесс.

## Обновление

Используйте `update-office` и отдельную локальную копию новой версии:

```bash
python3 scripts/office/update.py apply /путь/к/новой-копии --backup .office/backups/уникальное-имя
python3 scripts/office/update.py verify .office/backups/уникальное-имя
```

Обновляются только файлы шаблона по манифесту; пользовательские правки, свои сотрудники и навыки сохраняются. При конфликте — BLOCKED с исходными файлами и backup на месте. Сверяются SHA256, owner-блок и записи реестра; существования файла недостаточно. Backup удаляется только после успешной сверки, отдельной командой `cleanup`. Сбой не уничтожает backup.

Старый Claude-only офис мигрируется по известному исходнику, без реальных ученических миграций в этой поставке. Профиль и журнал сохраняются буквально. Старые цели с неизвестной датой подтверждения получают `needs-confirmation`; пользовательские сотрудники переносятся в draft до проверки. Неоднозначные имена и ручные общие инструкции требуют разрешения конкретного конфликта. Ни один такой конфликт не выдаётся за успешное обновление.

## Для автора шаблона

```bash
python3 scripts/office/materialize.py
python3 scripts/office/registry.py validate
python3 scripts/office/manifest.py --refresh
python3 -m unittest discover -s tests -v
```

`manifest.py --refresh` — только для авторинга чистого шаблона. Не используйте его для присвоения пользовательским файлам статуса template-owned. Список поставки явный: `.office/release-paths.json`. Упаковка ничего не исправляет: проверяет frozen manifest, равенство навыков, реестр и актуальную приёмку.

```bash
python3 scripts/office/package.py /локальный/кандидат.zip --candidate
python3 scripts/office/package.py dist/ai-office-starter.zip --acceptance-report docs/verification/acceptance.json
```

В ZIP нет Git, личных данных, профилей тестовых людей, `.env`, резервных копий, runtime-логов и symlink. Реальный офис с данными упаковывать этим способом нельзя. Политика и pre-push не являются абсолютной защитой терминала; Claude permissions не переносятся в Codex. Внешние действия выполняются только в явно разрешённом объёме.

Пошаговое начало — [guide/README.md](guide/README.md). Фактическая локальная приёмка и ограничения — `docs/verification/` в рабочем репозитории автора, вне клиентского ZIP.
