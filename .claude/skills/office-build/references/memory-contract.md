# Договор памяти и персонализации

До сохранения определи субъект: владелец, клиент, цитата/пример, неизвестно. Анкета от первого лица может быть чужой: принадлежность уточни. Тип записи: факт, намерение, предпочтение, гипотеза. «Хочу стать руководителем» — намерение, не должность. Статусы: confirmed / hypothesis / unknown / undecided. Подтверждённое требует источника и даты.

Покажи пересказ человеку и получи подтверждение ДО записи подтверждённых фактов. Прямая поправка текущего факта уже является подтверждением; старый импорт не отменяет её. Неясное существенное противоречие уточни при использовании. Правило общения: подтверждённое предпочтение → действие → область → исключение. Покажи преобразование смысла; не выводи психологию. Краткость не скрывает риски, нежелание вопросов не отменяет уточнения объекта и полномочий.

Можно не отвечать и запретить сохранение. Отказ — не «добрать позже». В профиль можно записать только разрешённую минимальную границу темы со статусом declined, без самого ответа. Не сохраняй запрещённый факт в журнал, summary, память, raw, входной JSON на диске или backup. Не копируй входящий материал до проверки разрешения его сохранить. Если нельзя сохранить даже тему — не записывай её и объясни, что между чатами невозможно помнить запрет без записи. Историей хоста офис не управляет. Удаление уже сохранённого требует конкретно разрешённого объёма, включая backup.

Каноны:
- me/profile.md — fenced office-profile JSON по me/_profile-template.md; не отдельная JSON-база.
- work/map.md — office-facts JSON, текущие факты о деле. Дополнительные предметные файлы содержат фактуру, карта — ссылки.
- me/goals.md — office-goals JSON, цели словами человека с scope/horizon/state, даже без коуча. Новая цель другой области не стирает ограничения. card коуча хранит ссылку на цель, не копию.
- knowledge/summary.md и owner-блок AGENTS — производные, не редактируются отдельно.
- build-log — ход знакомства и ссылки; исторический ответ не текущая истина.

Единый путь записи: `python3 scripts/office/personalize.py profile|work|goals`, JSON через stdin. Не создавай лишний временный файл с личными ответами. Для импорта work/goals используй --imported, конфликт не разрешай молча. Перед профильной записью перечитай текущий profile и сохрани все неотменённые записи. После ошибки записи проверь источники, не объявляй успех. Генератор меняет только owner-маркеры корня и производные, сохраняет общий договор. Полный профиль не нужен для нерелевантной операции.
