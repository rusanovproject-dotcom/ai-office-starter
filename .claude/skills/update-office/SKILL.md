# Обновление без потери памяти

Сначала прочитай корневые инструкции, текущую .office/template-manifest.json, profile и журнал только по необходимости. Вход — локальная распакованная копия новой версии с валидным манифестом. Внешнюю загрузку выполняй лишь в уже разрешённом объёме; этот навык сам не добавляет remote и не публикует офис.

Механика — `python3 scripts/office/update.py --help`; совместимая обёртка `bash scripts/office/update-office-sync.sh`.

1. Проверь источник и список template-owned файлов. Изменённые owner-файлы, оба skill-дерева и собственные сотрудники сохраняются. Одинаковое имя штатного skill не означает разрешение стереть правки ученика.
2. Для обновления используй `apply <локальная-новая-копия> --backup <новая-приватная-папка>`; не делай reset, stash, merge или рекурсивную замену каталога. Механизм проверяет candidate, создаёт backup с SHA256 и сравнивает изменения до записи. Конфликт — конкретный BLOCKED со старыми файлами на месте; сравни обе версии и реши в пределах выданных полномочий.
3. При успехе проверь данные командой `verify <backup>`: существования недостаточно, нужны совпавшие байты, в том числе законно пустых файлов, и восстановленный owner-блок AGENTS. Проверка backup также обязательна. Никогда не выдавай чтение манифеста за проверку данных.
4. При сбое сохрани backup, назови конкретный статус и путь восстановления. Rollback проверяется; не объявляй его успешным без сверки. Повторный запуск не должен терять данные.
5. Только после успешной сверки можно `cleanup <backup>`. Не удаляй произвольный каталог. Запрет сохранения соблюдается и в резервных копиях; удаление ранее сохранённого — отдельный явно разрешённый объём.

Для старого Claude-only офиса механизм использует известные исходные хеши. Ручные правки инструкций и навыков не исчезают под видом миграции. Старый личный блок переносится в новый AGENTS, CLAUDE становится @AGENTS. Неоднозначные личные/проектные инструкции требуют разбора, а не автоперезаписи. Цель из старой card сохраняется буквально в me/goals.md с происхождением; без доказательства подтверждения помечается для уточнения. Старая история не становится более свежим фактом.

Объясни человеку итог: что обновилось, что сохранено, что проверено и где остался конфликт. Файлы не доказывают, что новый клиент и хуки реально запущены; для этого нужна отдельная runtime-проба. Никакой миграции реальных офисов без явного запроса.
