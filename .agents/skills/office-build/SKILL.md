# Распаковка офиса

Сначала прочитай корневой AGENTS.md и references/memory-contract.md. Ведёт Никита: core читается по необходимости, его голос подчинён предпочтениям владельца. Журнал team/ops/build-log.md общий для обоих инструментов. Нет журнала и нет рабочего поручения — этап 1; есть журнал — продолжай открытый этап, не спрашивай отвеченное. Рабочая просьба выполняется сразу; знакомство не условие полезности.

Читай только текущий этап:
1. references/stage-1-meet.md — знакомство и материалы.
2. references/stage-2-me.md — профиль, подтверждение и подарок.
3. references/stage-3-coach.md — коуч по желанию.
4. references/stage-4-work.md — дело или ситуация в найме.
5. references/stage-5-win.md — полезная рабочая вещь.
6. references/stage-6-director.md — организация работы.
7. references/stage-7-projects.md — проекты и клиенты.
8. references/stage-8-memory.md — память и завершение.

Пиши статусы строго строкой `Этап N: название (открыт)` / `(готов)` / `(пропущен)`; последний статус этого номера решает. Закрывай только после `bash scripts/office/stage-check.sh N` и показа результата человеку. Проверка структуры не доказывает качественного интервью. Отказ от коуча даёт этапу 3 `(пропущен)`, остальные этапы доступны. При малом количестве ответов оставь известное; недостающие факты не выдумывай. За раз добирай не более трёх действительно нужных вводных, известное не спрашивай.

После каждого существенного шага запиши в журнал только этап, подтверждённое решение, ссылки на источники и следующий шаг. Не копируй туда профиль, цены, цели и отказанные личные ответы. Подробность, обращение и допустимые технические термины — по владельцу, а не жёсткое «ты» для всех.

Сотрудники регистрируются через team/registry.json и scripts/office/registry.py; карту вручную не правь. Навыки создавай в .agents/skills, затем материализуй. Полные имена и роли не смешивай. Файла роли недостаточно для настоящего subagent: в стартовом пакете роли работают в текущем чате.
