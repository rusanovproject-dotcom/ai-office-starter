# Этап 6 — Организация работы

Прочитай team/agents/director/core.md. Уточни только нужные сценарии и имя; роль — организация задач, не обязательный руководитель каждого ответа. Создай card.md с реальными сценариями, ссылками на профиль и цели, память по форме. В team/ops/today.md по шаблону запиши дату, IANA timezone и согласованный MIT; дневная задача не заменяет долгую цель. Если фокус не выбран — не выдумывай его.

Обнови имя/aliases и роль в registry.json, проверь карту через registry.py; aliases — имена, не роли. Пока status draft, не представляй Директора уже подключённым. Выполни одну пробную задачу организации работы: например, разложи синтетические задачи без потерь и выбери ближайший шаг. Сохрани разрешённый результат локально, например `results/director-trial.md`, и оцени по заранее названному критерию «все поручения сохранены, зависимости учтены, следующий шаг понятен».

Получив подтверждение результата владельцем, активируй через `python3 scripts/office/hire.py activate --id director` с JSON в stdin: `task`, `output` (резюме), `artifact` (относительный путь существующего непустого результата), `criterion`, `assessment`, `confirmed: true`. Ранее полученное подтверждение не спрашивай повторно; без подтверждения или разрешённого артефакта оставь draft и этап открыт. Карточку и память не заменяй текстом пробы. Затем `bash scripts/office/stage-check.sh 6` должен пройти до закрытия; проверка требует active. Никакого обещания фонового мониторинга без работающего механизма.
