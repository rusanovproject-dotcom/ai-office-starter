# Новый сотрудник

Прочитай корневой AGENTS, team/registry.json и core Демиурга. Общий стиль владельца уже известен: читай личный блок и только нужные записи профиля. Не начинай полное знакомство заново.

1. Определи результат и повторяемую задачу. Если имеющаяся роль справляется, объясни и используй её. Для новой роли — согласованное имя и реальные сценарии, область, запреты, доступы.
2. Найди доступные источники компетенции и пример качественного выхода. Выбери предметный каркас Демиурга: `content-voice.md` для голоса, `sales-lite.md` для сделки, `niche-helper.md` для другой ниши. Каркас не может быть единственным источником компетенции: нужен доступный предметный материал и пример качества. Если методики/инструмента нет — честно сузь обещание до имеющейся компетенции; существенный незакрытый запрос пометь блокером. Не изобретай эксперта по названию профессии.
3. Через `python3 scripts/office/hire.py --help` создай draft: core, персональную card, память и запись в registry. Связи на профиль и каноны вместо копирования биографии. Aliases — имена, role отдельно. Источники и пределы присутствуют в core. `competence` — `local` для ограниченной роли или `expert` при заявленной экспертности; второй вариант требует независимой доменной проверки. Нет оснований экспертизы — не называй роль экспертом.
4. Выполни реальную локальную пробную задачу по этим инструкциям. Сохрани вход, выход и оценку по заранее названному критерию. Наличие файлов/составленный план пробы не успех. Проверь неподходящий запрос: роль должна вернуть его инициатору или назвать границу. Для экспертной роли нужна независимая доменная оценка, иначе не обещай экспертный статус.
5. Покажи карточку и результат владельцу. Только подтверждённую завершённую роль активируй с evidence пробы и подтверждением. Обнови читаемую карту через registry.py. Проверь вызов по имени/алиасу, коллизии и отсутствие вызова по упоминанию.

В стартовом пакете сотрудник — роль в текущем чате, не настоящий субагент CLI. Реальный parallel/native adapter не создаётся автоматически. Внешние сообщения и публикации не выполняются. Инициатор отвечает за конечный результат после найма.

## Доказательство завершённой пробы

`hire.py activate --id <id>` принимает JSON через stdin. Сначала сохрани настоящий локальный результат, затем передай его относительный путь внутри `results/` или `projects/`. Инструкции офиса, core/card/memory и сам источник методики не могут быть артефактом пробы или доменным отчётом. Минимальный пример для ограниченного помощника:

```json
{
  "task": "Подготовить ответ на заявку без отправки",
  "output": "Черновик с одним следующим шагом",
  "artifact": "results/reply-probe.md",
  "criterion": "Нет выдуманной цены; есть следующий шаг; ничего не отправлено",
  "assessment": "Цена не указана, запрошено удобное время, отправки не было",
  "confirmed": true
}
```

`confirmed: true` передавай только после фактического подтверждения владельца. Непустая фраза «ответ готов» без документа, критерия и оценки не позволяет активировать роль. Скрипт фиксирует путь и SHA256 результата в card/memory, проверяет доступность источников новой роли повторно. Для встроенного сотрудника без metadata sources остаётся его штатная методика; та же проба и подтверждение обязательны.

Для `competence: "expert"` добавь `domain_review` с полями `reviewer`, `verdict: "pass"`, `artifact` — путь к отдельному содержательному отчёту независимого предметного проверяющего. Роль не оценивает сама себя. Файл и заявленная личность не доказывают независимость технически: инициатор проверяет, кто реально сделал ревью, его вывод и соответствие предмету. Нет независимого инструмента/проверяющего — экспертная роль остаётся draft, либо с владельцем согласуется ограниченная роль local без экспертных обещаний.
